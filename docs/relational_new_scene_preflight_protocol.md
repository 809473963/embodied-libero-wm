# 新development场景生成与重放检查协议

日期：2026-10-08。用户授权“继续”。此轮只做生成/重放技术检查，不训练、不执行C0策略或任务收益比较。

仅执行既有保留表中的20个development seeds（10任务各2个）；40个confirmation seeds不生成。每个seed在构造环境前设置Python/NumPy RNG，构造后再次设置环境seed，只调用一次底层`env.env.reset()`，避免原wrapper在RandomizationError上无限重试。失败保留，不换seed补样本。

成功生成后，用生成的sim-state重新产生规范初始观测；检查初始G2必须UNIQUE且referent与官方目标一致。无效者记录原因，不执行其动作检查。不按任务success或后续动作好坏选场景，不加载任何`.pruned_init`或HDF5数据。

每个有效seed最多三个fresh环境：生成、同seed重新生成、同seed fresh reset后恢复保存状态。根时刻sim-state、8实体pose、RGB、12维proprio必须完全一致；三次执行相同的24步诊断动作，逐步物理记录和末端图像也必须完全一致。保存状态恢复检查仍要求fresh相同控制器初始化；不声称任意中途仅恢复qpos就足够。

诊断动作：前8步手臂零增量/开夹爪，中8步z轴归一化控制+0.1/闭夹爪，后8步零增量/闭夹爪。不追求任务成功，不调用模型，无根据观测选择后续动作。上限60次构造/单次reset尝试、1,440次显式env.step；环境初始化内部的物理计算不冒充计入控制步。每组动作提交前记入预算，无自动失败重试。

布局指纹使用两碗、盘、cookies、ramekin五个实体body原点与四元数；规范化四元数正负号并保存8位小数哈希。近重复要求五实体位置的最大差≤1mm且最大朝向差≤1度，另报告原始差异。它是保守的几何重复检查，不是任务难度/语义场景独立性的充分证明。

生成场景与可核查的40个旧A0初始布局、以及本轮此前接纳场景比较。重复保留记录但不列为新增development scene，不替换。历史C0训练布局没有全面对照，因此不能声称“C0从未见过”；可声称的范围仅是与这40个已审计布局不同。

输出`results/relational_new_scene_preflight`：runtime、初始state/RGB/proprio、三次重放数组、逐seed记录、manifest及布局比较analysis。遇到重放不一致停止，保留技术block，不给科学失败结论；随机初始化/grounding无效则按注册规则记拒绝并处理下一seed。

通过本轮只说明能生成且可信地重放部分新的development布局。后续C0访问分布、持有且相对盘位置分层、H24事件采集还需具体预算协议；confirmation继续封存。

冻结前4项测试通过：四元数符号等价、位置与旋转近重复检查、速度差不伪造新布局、固定诊断动作合法。未重跑全仓库测试。
