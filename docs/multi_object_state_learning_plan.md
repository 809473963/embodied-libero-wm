# 后续主线：统一对象状态与多关系感知

日期：2026-10-09。根据多物体审计更新研究范围，以下是后续实验设计，不是已经训练出的能力。

## 目标与边界

不再将目标—盘单一关系作为感知主目标。估计任务相关对象的共享状态，由共享状态计算几何关系，再独立学习/检验接触、抓取、支撑和动作后事件。当前状态可靠是必要基础之一，但不把事件可靠性假设为自动成立。

已完成的多物体审计显示：另一碗—盘/夹爪误差55.87/76.63 mm，两条关系路径闭合差28.68 mm。共享辅助位置虽按构造闭合，碗间关系误差仍85.49 mm。因此既不能保留目标物偏科，也不能认为“换成共享状态”本身就解决精度。

## 节点与状态契约

统一登记两碗、盘、cookies、ramekin、table、cabinet、stove以及机器人grip frame。明确每个节点是可移动对象、操作参照、支撑、潜在障碍还是机器人；不能只凭物体名字永久指定任务相关性。语言选择目标应作为身份/grounding模块，物理槽位训练不能冒充自然语言理解。

先逐项检查旧数据能否提供一致的body原点、姿态、速度、可见mask、身份与接触监督，以及其部署输入来源。位置统一world或同一个经验证的机器人坐标系。对象中心、body原点、可见质心不得混用。table等静态节点的模型先验单列，不用静态背景的简单成绩掩盖移动对象错误。

机器人位置和姿态应尽量来自合法proprio/关节正运动学，但必须核验frame、零位、offset和时序。本批22起点EEF位置与grip site一致，不足以替代完整姿态契约。

## 第一项匹配学习实验

先在旧场景内部冻结统一节点位置任务；姿态、速度和接触扩展按标签可用性分阶段加入，不把所有输出一开始堆成不可解释的大loss。

- 共享状态模型：为每个实际纳入的对象输出同一坐标系位置；两两位置差由这些节点计算。
- 匹配基线：同样输入、同样训练场景和预算的独立关系输出，覆盖同一组节点/边。
- 合法机器人测量节点：与视觉估计节点分开报告；不能将GT机器人旋转混入推理而不标记。
- 两组使用相同自然RGB/history/proprio契约，不改变teacher事件定义。先检查当前状态，再接冻结动力学或新的事件读出。

这不是直接使用当前辅助uv/depth头取代主头；辅助头的定位误差已知较大。也不继续在现有9开发场景上选择输入、权重或checkpoint。模型选择先留在旧场景分组验证，最后才安排独立确认。

## 评估必须成套报告

1. 逐节点3D位置误差与轴向偏差；对移动对象、参照、支撑/障碍和机器人分组。
2. 所有纳入关键关系的误差矩阵，包括碗—碗、碗—盘、碗—夹爪、夹爪—盘及与支撑/障碍的关系；不得只选目标—盘。
3. 关系闭合/路径一致性，以及每起点最坏关键关系。共享状态闭合为0只是构造性质，不能当泛化成绩。
4. 按遮挡、接触、移动/静止、身份易混淆分层，并报告每层独立场景数量。
5. 真值状态与预测状态分别输入同一个事件预测器，区分感知误差、状态不充分和事件模型误差。接触/支撑不能仅由几何距离充当真值。

不要求所有背景对象达到同一毫米阈值。以事件与决策需要制定分组精度要求，但不能事后根据最好看的关系修改gate。先报告误差曲线与范围，避免再次将单个点阈值当机制证明。

## 明确的停止条件

节点身份/坐标/标签契约不一致则停止依赖训练并修复。共享状态只改善代数闭合而未改善关键关系误差，不支持替换当前方案。当前状态变准但真实事件仍误报，则单独处理状态变量、事件覆盖和预测目标，不能再把全部责任归为视觉。

本计划尚未运行新节点模型、确认实验或controller。下一具体工作是旧数据的统一节点监督清单与合法机器人frame验证，随后才冻结匹配训练预算。

证据：[多物体审计](multi_object_relational_perception_audit.md)。
