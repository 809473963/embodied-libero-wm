# 项目进度说明：多对象感知仍是当前主要短板

截至：2026-10-09 已完成实验。项目：embodied-libero-wm。

**项目已从“学习T1语义分数并排名候选”，转向“感知任务相关对象的状态和关系，预测动作带来的真实变化”。当前已完成真实候选效用审计、关系与事件数据建设、动力学及自然感知试验，以及首轮多对象位置匹配训练。尚未形成经过独立确认、能稳定提高任务成功率的新控制系统。**

最新结果显示，共享对象位置能够保证关系一致，但没有自动提高精度；第二只碗仍存在约161mm的位置误差。下一步拟检查视觉定位、物体身份和场景覆盖，并测试显式视觉—坐标对应。该方案已完成初步文献讨论，尚未实施。

## 一、目前的研究目标

学习两只碗、盘、其他相关物体及机器人之间的状态和关系，再预测动作是否使这些关系发生有用变化。抓住、抬起、释放和稳定放置是需要独立检验的事件，不能仅凭物体位置接近就判定成功。

C0目前提供基线策略、部分访问状态与数据来源；它不是最终方法必须永远遵循的动作限制。但已完成的候选效用结果仍依赖特定候选池、时域和固定C0续行，不能外推到任意动作生成方式。

研究范围已从目标—盘扩展至全部纳入的任务相关对象。[当前主线计划](multi_object_state_learning_plan.md)是最新范围；较早几何报告中“只关注目标—盘”的下一步建议已被这一范围更新取代，旧结果本身保留。

## 三、最新一轮具体完成了什么

监督审计覆盖旧13场景的4,843条去重观测。8个环境实体为两只碗、盘、cookies、ramekin、桌子、柜子和炉子，加上夹爪构成9节点、36条无向位置差关系。位置、姿态和速度记录可得；其余5个环境实体的可见mask尚未生成。接触记录不等于有向支撑或稳定抓取真值。

只用合法关节位置与固定机器人模型进行正运动学检查，最大位置误差为0.558mm、最大旋转误差为0.047°，通过预定工程预算。位置模型直接使用合法EEF测量作为机器人节点。[监督与坐标审计](unified_object_state_audit.md)

匹配训练采用旧场景3折、3个随机种子、2种结构，共18次拟合，每次固定40轮。输入为初始及当前RGB、合法proprio和上一动作；共享模型输出对象world位置后计算关系，基线独立输出同一36条关系。两者使用相同关系损失和公共网络结构，输出头参数量不同，未宣称完全等参数。

## 四、当前瓶颈及证据边界

**已观察到：多对象位置感知不均衡。** 第二只碗是明显短板，共享状态的一致性约束未修复它。这里的碗1/碗2是物理槽位，不等于已解决语言指代与持久身份。

**尚未隔离：定位、身份、可见性、数据覆盖和读出能力。** 新多对象OOF预测还需分层核查，才能判断是找错像素、交换身份、视野不足还是跨场景位置分布问题。较早自然模型在另一批22起点上的事后身份交换几乎无改善，但不能把该诊断直接套到本次模型与旧场景三折结果上。[较早身份诊断](relational_natural_state_handoff.md)

**独立存在：事件预测仍不可靠。** 较早开发诊断将全部状态替换为真值后，On事件仍有误报与漏报；真正持有起点的释放事件TP/FP/FN仍为4/2/2。其真实释放正例只有6条、来自3个场景。因此“先把位置估计准”值得做，但不能承诺自然解决抓取与放置事件。[几何与事件诊断](relational_geometry_diagnosis_interpretation.md)

**尚未建立：其他任务泛化与净控制收益。** 当前对象模型不是通用物体识别器，已有开发数据反复参与诊断，真实状态动力学有信号也不是部署控制成功的证明。

## 五、刚讨论的视觉—坐标对应方案处于什么状态

状态：**已做初步论文检索和概念讨论，尚未冻结实现、生成新的关键点监督或启动训练。**

项目已具备world坐标标签和相机几何基础。拟议改进是显式学习“哪些像素属于哪个对象、哪些图像点对应物体的哪些三维部位”，再结合相机标定、已知物体几何或深度估计恢复坐标。仅增加坐标轴或继续直接输出xyz不保证精度提升。

此前已尝试辅助uv/depth监督，但其重建路径误差较大，且不是主输出必须经过的几何求解路径；因此新方案需要与旧辅助方法明确区分并做对照。

| 已检索工作 | 可借鉴内容 | 应保留的限制 |
|---|---|---|
| [PVNet](https://openaccess.thecvf.com/content_CVPR_2019/html/Peng_PVNet_Pixel-Wise_Voting_Network_for_6DoF_Pose_Estimation_CVPR_2019_paper.html) | 像素投票定位关键点，再由2D—3D对应求位姿 | 需要已知几何对应，碗的对称性需处理 |
| [NOCS](https://arxiv.org/abs/1901.02970) | 像素与统一物体坐标对应 | 原方法结合深度恢复尺度与位姿，不是单目RGB精度保证 |
| [Dense Object Nets](https://arxiv.org/abs/1806.08756) | 物体表面点的密集视觉对应与实例描述 | 对应稳定不等于世界坐标已精确 |
| [Transporter Networks](https://proceedings.mlr.press/v155/zeng21a/zeng21a.pdf) | 使用空间一致的视觉表示学习操作位移 | 原输入几何条件与当前单目设定不同 |
| [FoundationPose](https://nvlabs.github.io/FoundationPose/) | 利用物体先验做位姿估计与跟踪 | 需要CAD或参考图像等条件，不自动解决相似物体身份 |

这些是此前对话检索所得的方法参考，不是已在本项目复现的结果，也不是最新文献的系统综述。

## 六、下一步建议顺序

1. **先核查现有多对象OOF错误。** 对全部关键对象报告可见性、身份交换诊断、位置分布和逐场景误差，重点检查第二只碗。OOF指每帧预测来自未用该场景拟合的模型；它仍属于反复使用的内部开发评估。
2. **做坐标恢复上限对照。** 用真实二维关键点与已知物体几何检验三维求解精度，再换成预测关键点；真实身份与预测身份分开比较。先确定几何链能否奏效，再投入视觉模型。真值输入只用于诊断，不冒充部署输入。
3. **在旧场景内部冻结一项视觉对应学习实验。** 与当前直接回归比较，保留全部对象关系、最坏关键边与无图像基线。若使用深度，区分训练监督、诊断上限和部署输入三种角色。
4. **位置改善后再检验事件误差传递。** 同一事件模型分别接真值与预测状态；补足真实抓取、释放转移的独立场景覆盖，再考虑独立确认与控制实验。

以上为建议，不能表述为已经执行或已经证实有效。当前没有理由仅凭共享结构闭合或普通位置指标改善就宣布事件模块和controller可以可靠工作。
