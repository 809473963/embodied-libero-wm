# 状态分层H24关系事件采集协议

日期：2026-10-07。用户授权“继续下一步”。本轮采集已有场景的较长开环事件分支，不训练、不部署控制器。

## 冻结选择

先冻结[选择规则](../configs/relational_event_h24_selection.json)，再对既有20个init31/34的A0轨迹登记起点。只在t=16,24,…,240检查当前/历史谓词，每场景每层取首次满足者：

- 接近未接触：当前无目标夹爪接触，目标body原点到grip site距离≤0.08m。这是粗接近代理，不是表面距离。
- 双指接触但未达脱离持有：当前双指腹接触且v1 detached未成立。
- 已脱离持有：因果v1 detached成立。
- 有持有历史的释放在盘上：当前On、非夹爪接触、无夹爪接触，且过去已观察到detached。不要求未来保持成功。

不读取success或未来动作后果进行选择。不满足的层记录为缺失，不更换场景补齐。相同scene/time在不同层重复时合并，保留多个层标签；不同层统计不能相加当独立数量。所用原始数据已暴露，本规则是透明的探索性采样，而非盲预注册发现。

[登记结果](../configs/relational_event_h24_cases.json)：38个不同起点；四层覆盖12、12、11、10个旧场景（可重叠）。按原scene绑定所有分支，init31/34仅沿用既有拟合/开发来源，不称新泛化集。

## 完整24步方案

每个起点执行6种固定方案，全部在起点已知，运行中不调用C0反馈：

1. 原C0在该起点已经规划的H8，之后16步手臂零增量、夹爪维持第8步指令。
2. 24步手臂零增量、夹爪维持根时刻A0第一步方向。
3. 24步手臂零增量、夹爪打开。
4. 24步手臂零增量、夹爪闭合。
5. 前8步平移控制z轴+0.15、夹爪闭合，后16步手臂零增量、继续闭合。
6. 前8步平移控制z轴−0.15、维持根时刻夹爪方向，后16步手臂零增量、打开。

±0.15是归一化控制输入，不是米；“抬升/下降”是动作配方名称，不保证物体产生该事件。没有读取原轨迹t+8以后的C0动作作为新计划。零手臂增量也不保证完全静止，实际后果必须记录。

H24在20Hz下名义1.2秒，给10间隔稳定窗口留出时间，但不保证发生释放放置。v1标签与所有阈值不修改，记录H8/H16/H24终点及整个过程标签。旧H8预测器不自动外推到H24。

## 数据与预算

38×6=228条正式分支；第一起点另做三次相同方案0技术preflight（两次RGB开、一次关），合计231次运行、最多25,152控制步，包含fresh prefix重放。每批提交前计入预算；失败不自动重试、不重置预算。

preflight要求RGB开关不改变完整物理数组，重复RGB一致，root/H24 RGB-proprio与原snapshot接口一致，原前缀及方案0前H8与旧轨迹完全一致。正式每条前缀必须复现旧记录。之后24步不要求与旧C0续行一致，因为动作尾部已改为固定方案。

记录全部prefix及H24物理状态/接触/完整动作；自然RGB/proprio记录初始帧0和t−10…t+24（共36帧）。自然记录不参与动作选择。复算接触、v1标签、完整动作配方、时间戳和哈希，再按原scene/anchor/stratum报告事件形成、消失、缺失与另一只碗覆盖。官方success只作环境诊断，不作为筛选或新utility。
